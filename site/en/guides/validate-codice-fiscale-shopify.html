Formal Codice Fiscale validation on Shopify: how it works

Formal Codice Fiscale validation on Shopify takes more than counting sixteen characters. A serious check verifies that the code’s parts are coherent without turning into an identity check.

Updated 12 November 2026

How a 16-character Codice Fiscale is built

An individual’s Codice Fiscale has sixteen characters, each with a precise role. Take the sample code RSSMRA85T10A562S:

  • RSS, positions 1-3: three letters derived from the surname.
  • MRA, positions 4-6: three letters derived from the first name.
  • 85, positions 7-8: the last two digits of the birth year.
  • T, position 9: the month, written as a letter.
  • 10, positions 10-11: the day of birth. For women 40 is added, so 10 becomes 50.
  • A562, positions 12-15: the code of the municipality of birth, one letter and three digits. People born abroad have a code starting with Z.
  • S, position 16: the check character, calculated from all the others.

Months as letters

The month is written with one of twelve letters: A January, B February, C March, D April, E May, H June, L July, M August, P September, R October, S November, T December. Any other letter in ninth position makes the code invalid. The month also decides which days are allowed: 31 April, 31 June or 30 February do not exist. 29 February is accepted, because the century cannot be derived with certainty from two digits of the year.

The check character

The last letter comes from a calculation on the first fifteen characters: each character has a value, different for odd and even positions, and the remainder of the sum divided by 26 gives the final letter. A single wrong letter or digit is enough for the check to fail. RSSMRA85T10A562X has the same structure as the sample code, but its last letter does not match the other characters, so it is invalid.

Omocodia

Two people can end up with the same code. In that case the Italian Revenue Agency tells the codes apart by replacing some digits with letters: L for 0, M for 1, N for 2, P for 3, Q for 4, R for 5, S for 6, T for 7, U for 8, V for 9. Only the seven numeric positions for year, day and municipality can change, and the check character is recalculated. For example, RSSMRA85T10A56NH is a valid omocodia form, with N in place of 2.

11-digit numeric codes

Companies, public bodies and provisional codes have an 11-digit Codice Fiscale with no letters. The last digit is a check digit calculated on the first ten with the same algorithm used for the Italian VAT number. CF Ready checks the 11 digits and the check digit, rejects 00000000000 and treats the value as a Codice Fiscale: VAT numbers stay outside CF Ready. Today these codes run into the native field limit described below.

Why a regex is not enough

A simple regular expression can accept 31 April or reject a valid omocodia code. Validation has to interpret the parts of the code, not just their appearance. Before checking, CF Ready removes outer spaces and reads the value in uppercase, without changing what the customer typed. Inner spaces, dots and hyphens make the value invalid.

The limit of Shopify’s native Codice Fiscale field

Since 6 November 2026, the Codice Fiscale field, one of Shopify’s native Italian tax fields, applies its own check: it accepts only the ordinary 16-character structure and rejects numeric and omocodia Codice Fiscale codes before any app runs. CF Ready treats them as valid, but until Shopify fixes the field, customers with these codes cannot complete the order. In tests on the same day, the native check did accept a wrong check character and a non-existent month: those are the errors CF Ready flags.

Formally valid does not mean it belongs to that person.

CF Ready does not query the Italian Revenue Agency and does not certify identity, existence or ownership. It reduces input errors before the order is completed.

How Codice Fiscale validation works at checkout

The check runs inside Shopify’s Validation and returns a message only when the merchant’s rule requires it, for example when you require Codice Fiscale at Shopify checkout. A short hint about the cause is added to the merchant’s text, so the customer knows what to fix. Codice Fiscale values are not saved on CF Ready servers or sent to external providers. You can try all these cases in the app’s simulator before activating the rule.

Handling uncertain cases

A technical error or uncertain configuration or plan state leaves checkout open. That is different from a field that breaks an active rule: in that case CF Ready shows the expected error.

Frequently asked questions

Does a formally valid Codice Fiscale necessarily belong to the customer?

No. Formal validation checks that the code is built correctly. It does not query the Italian Revenue Agency and cannot tell whether the code exists or belongs to the person entering it.

Can customers type Codice Fiscale in lowercase or with spaces?

Lowercase and spaces at the start or end are fine. Inner spaces, dots and hyphens make the value invalid, and the message asks the customer to enter it without separators.

Why does Shopify reject an omocodia Codice Fiscale?

Since 6 November 2026, Shopify’s native field rejects omocodia and numeric codes before any app runs. CF Ready treats them as valid, but it cannot override Shopify’s rejection.

What does the customer see after a Codice Fiscale mistake?

They see the message chosen by the merchant, in Italian or English, followed by a short hint about the cause: length, characters, order of letters and numbers, or check character.
